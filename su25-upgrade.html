PART 1

SU25 — Profile Upgradation

Why SU25 is required?

  • Two standard tables — USOBT (T-Code vs Authorization Object) and USOBX (check indicators for USOBT).
  • After upgrading SAP to a new release, all roles and transaction codes need adjustment.
  • SU25 is the transaction used to upgrade the Profile Generator.
  • Has 6 steps — which ones you run depends on whether Profile Generator was already in use in the last release.
STEP 1
Initially Fill the Customer Tables

One-time activity. Used only if Profile Generator was never used before. Copies SAP data into customer tables USOBT_C, USOBX_C.

STEP 2A
Preparation — Compare with SAP Values

Prepares the comparison. Must be executed first, before 2B/2C/2D.

STEP 2B
Compare Affected Transactions

Compares your changed check indicators/field values (from SU24) against new SAP defaults. Status shows "to be checked" or "checked"; option to copy remaining SAP defaults in bulk.

STEP 2C
Roles to Be Checked

Identifies roles affected by authorization data changes — status "profile comparison required". Alternative: assign users the SAP_NEW profile temporarily instead of fixing every role right away.

STEP 2D
Display Changed Transaction Codes

Lists roles containing old T-codes that got replaced by new ones. Double-click to jump to the role and fix it.

STEP 3
Transport the Customer Tables

Transports changes from Steps 1, 2A, 2B to other systems (Dev → QA → Prod).

STEP 4
Check Indicator (Optional, via SU24)

Check/Maintain → authorization added to Profile Generator. Do Not Check → object skipped entirely. Can also edit authorization templates.

STEP 5
Deactivate Authorization Object Globally (Optional)

Switches off an authorization object system-wide.

STEP 6
Copy Data from Old Profiles

Creates roles from manually-generated profiles; roles then need manual tailoring and checking.

Which steps matter most in a real upgrade? 2B and 2C get repeated every upgrade/support pack — 2B to review SAP's new defaults, 2C to identify and fix affected roles. Step 1 runs only once, ever.
PART 2

Security Consultant Checklist — Pre & Post Upgrade

Pre-Upgrade (Preparation Phase)

  • Run SU25 comparison (Step 2A first) to see what's changing in the target release.
  • Impact analysis on custom roles — SUIM/role usage reports to flag obsolete/renamed T-codes.
  • Map classic T-codes to Fiori apps and plan catalog/group assignments.
  • Backup the GRC ruleset — export ARA Functions, Risks, Rules.
  • Take a pre-upgrade SoD baseline snapshot for later comparison.
  • Check GRC version compatibility with the target release.
  • Role and user cleanup — remove unused roles, expired mitigations, orphan users.
  • Test critical roles in sandbox/QA with SU53 and ST01 traces.

During Upgrade (Technical Window)

  • Monitor SU25 Step 2C as SAP delivers new authorization defaults.
  • Review and flag only — no role edits yet at this stage.
  • Coordinate with Basis to pause GRC repository sync jobs during downtime.

Post-Upgrade (Validation & Stabilization)

  • Complete SU25 Steps 2D and 3 — fix roles with replaced T-codes, transport final changes.
  • Mass regenerate roles via PFCG (SUPC/mass generation).
  • Run authorization traces (ST01/SU53/STAUTHTRACE) on key users and Fiori apps.
  • Validate Fiori Launchpad — catalogs, groups, tiles, OData services.
  • Full GRC repository sync — Authorization objects, Actions, Permissions, User/Role master data.
  • Reconcile SoD ruleset — compare baseline vs post-upgrade risk analysis.
  • Test EAM — Firefighter ID logins and SM20/CDHDR log sync.
  • Verify custom (Z) authorization objects still work.
  • Hypercare support for 2-4 weeks — resolve authorization tickets.
  • Update documentation — role matrix, RAR mitigation docs, ARM request forms.
30-second interview answer Before the upgrade, I do role impact analysis and take a GRC baseline. During the upgrade, I monitor SU25 Step 2C where SAP flags new authorization changes. After the upgrade, I run SU25 Steps 2D and 3, regenerate roles in PFCG, run authorization traces, validate Fiori and GRC, then support hypercare for a couple of weeks.
