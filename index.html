GRC MSMP Workflow

Simple notes for interview revision

All four GRC modules — ARA, ARM, EAM, BRM — use the same workflow concept. Every workflow has 7 configuration steps, and each module uses routing, approval paths, and stages for its own operations.

Memory line Process → Rules → Agents → Templates → Paths → Route → Generate

Step 1: Process Global Settings

  • Sets the Initiator Rule for a Process ID (example: SAP_GRAC_ACCESS_REQUEST)
  • Rule: each Process ID can have only ONE active Initiator Rule — no more, no less
  • Initiator Rule = starts the request. It checks one unique condition.
  • If a custom condition is needed, you create a BRF+ rule instead, and declare its possible results
  • Routing Rule = works like the initiator rule, but is used for handling exceptions during the workflow (not at the start)
  • Both Initiator and Routing rules must have their results declared, and routings must be set up

Step 2: Maintain Rules

  • This is a master list of all rules used anywhere in the workflow
  • Any new rule you create must be added here
  • The default initiator is also set in this step
  • You must list all the possible results a rule can return (using the Results button) — these results get connected to a Path later, in Step 6

Step 3: Maintain Agents

  • Agent = the person who will approve or get notified during the workflow
  • Unlike the Initiator Rule, an Agent Rule's condition does not need to be unique — it can return multiple people/results at once if the process needs it
  • 4 ways to define an agent: GRC API rule, PFCG User Group, PFCG Role, Directly Mapped user

Step 4: Variables and Templates

  • This step defines the variables that can appear inside the notification email/template sent to users
  • Example: request number, requester name, approver name — these get plugged into the notification text
  • The rule and its variables must be declared here

Step 5: Maintain Paths

  • Here you decide the approval path: will it be 1 stage or 2 stages (or more)?
  • You set a Path ID and connect it to an Agent ID
  • Example: GRAC_DEFAULT_PATH has 2 stages — Manager and Security
  • This step is where you decide how many people need to approve, and in what order

Step 6: Maintain Route Mapping

  • This step connects the rule result (from Step 2) to the correct path (from Step 5)
  • Example: Result GRAC_DEFAULT_RESULT is mapped to Path GRAC_DEFAULT_PATH
  • Important rule: The Global Initiator must always be used. If you need multiple different paths, the Global Initiator must return different result values for each case

Step 7: Generate Versions

  • The final step — this saves and activates all the changes you made across the previous 6 steps
  • Nothing goes live until this step is done
One-line interview answer MSMP workflow has 7 steps. First, an Initiator Rule decides if and how a request starts. Then we list all rules, define agents (approvers), set up notification variables, build approval paths with stages, map rule results to those paths, and finally generate a version to activate everything.
